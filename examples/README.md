# Course demonstrations

These 31 Python programs were supplied by Mark from last year's course in
`AllDemos.zip`. They are preserved as supplied. The number in each filename
identifies its session, for example `demo_4_lists.py` belongs to Session 4.

They provide evidence of the examples and techniques demonstrated in class.
Current canonical reference material is in `sessions/`; where older demo
comments conflict with the revised references, use the current references and
flag the discrepancy rather than silently modifying a demonstration.

## Requirements for the forthcoming AI tutor package

Use the current date and the organiser's session schedule as a guide to what
has probably been covered. Session dates have not yet been supplied: do not
infer them from filenames, file timestamps, or last year's calendar. Use the
course's Europe/London timezone when interpreting scheduled dates.

Scheduled coverage is a default estimate, not proof that a student has
completed a session. A student's stated progress and explicit updates from
the organiser take precedence. If a session is scheduled for today and its
completion is unclear, ask whether the student has attended it before
assuming its material has been covered. Keep publication/release decisions
separate from this estimate of teaching progress.

Before publication, record any known inaccuracies or intentional error
examples in the demo catalogue. Several programs include commented-out
failing examples as teaching prompts; these must not be presented as
recommended working code. The large NumPy timing demonstration allocates
50 million elements and should be identified as a resource-intensive demo.

The current examples are an intake collection, not yet a published AI tutor
package. Assessment policy, environment guidance, and release dates remain
to be supplied.
