## Notes for the tutor

These 31 Python programs were supplied by Mark from last year's course in
`AllDemos.zip`. They are preserved as supplied. The number in each filename
identifies its session, for example `demo_4_lists.py` belongs to Session 4.

They provide evidence of the examples and techniques demonstrated in class.
Current canonical reference material is in `sessions/`; where older demo
comments conflict with the revised references, use the current references and
flag the discrepancy rather than silently modifying a demonstration.

## Supporting data

These programs are samples of the lecturer's coding style and classroom
examples, not a self-contained runnable bundle. Their CSV inputs are not
required for that purpose and need not be supplied for the tutor package.

- `grades.csv` — `demo_6_files.py` and `demo_6_files2.py`
- `id_to_names.csv` — `demo_6_files2.py`
- `test.csv` — `demo_6_test1.py`
- `first_year_marks.csv` — `demo_8_scatterplot.py`

These input files were not included in the archive. `test-m.csv` is generated
by `demo_6_test1.py`, so it is not a missing input.

## Requirements for the forthcoming AI tutor package

Use the current date and the organiser's
[2026 session schedule](../ai-helper/SESSION-SCHEDULE.md) as a guide to what
has probably been covered. Do not infer dates from filenames, file timestamps,
or last year's calendar. Use the course's Europe/London timezone when
interpreting scheduled dates.

Scheduled coverage is a default estimate, not proof that a student has
completed a session. A student's stated progress and explicit updates from
the organiser take precedence. If a session is scheduled for today and its
completion is unclear, ask whether the student has attended it before
assuming its material has been covered. Keep publication/release decisions
separate from this estimate of teaching progress.

Some programs deliberately illustrate failures or contain commented-out
nonworking examples. For instance, `demo_3_float_fail.py` shows why an exact
floating-point equality test can fail, and `demo_7_numpy2.py` comments out a
call to `math.sin` on an array because that call fails. Do not present such
examples as recommended working code. `demo_7_numpy3.py` allocates an array
of 50 million elements and creates large lists to compare performance; it is
resource intensive and should not be run casually while tutoring. These are
not a substitute for the current canonical explanations.

These demonstrations are included in the AI tutor package. Environment
guidance is recorded in
[the course environment briefing](../ai-helper/COURSE-AI-ENVIRONMENT.md).
The [tutor instructions](../ai-helper/TUTOR-INSTRUCTIONS.md) record Mark's
current guidance on formative assignments, learning with AI, and the class
test. Do not infer dates or assessment arrangements from these old examples.
